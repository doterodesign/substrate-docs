Substrate treats color as *intent*, not as a fixed palette. Rather than specifying hex values or manually crafting light and dark variants, you tell the system what a color is *for* — and provide just two perceptual parameters per role. Substrate handles the rest: lightness is never authored by hand. Instead, the APCA (Advanced Perceptual Contrast Algorithm) solver calculates the exact lightness value that achieves compliant contrast on whatever surface the color appears against.

## The intent model

Every color role in your config is described using two OKLCH parameters:

- **`hue`** — an angle on the color wheel, from `0` to `360`
- **`chroma`** — colorfulness, from `0` (achromatic) to approximately `0.4` (the maximum depends on hue and display gamut)

You never set `lightness`. Substrate derives it automatically — solving for the target APCA contrast value appropriate to each semantic use case (e.g. text on surface, icon on background, border against fill).

## Color config shape

```json
"color": {
  "primary": { "hue": 160, "chroma": 0.18 },
  "neutral": {
    "light": { "hue": 210, "chroma": 0.02 },
    "dark": { "hue": 220, "chroma": 0.04 }
  },
  "error": { "hue": 0, "chroma": 0.22 },
  "warning": { "hue": 40, "chroma": 0.20 },
  "success": { "hue": 145, "chroma": 0.20 }
}
```

## Multi-stop intent (light/dark shift)

Some colors need to shift their personality between light and dark mode — a neutral might feel cool and blue-gray in light mode, but richer and warmer in dark mode. For these roles, provide separate `light` and `dark` objects instead of a single intent. Substrate interpolates between them when computing mode-specific tokens:

```json
"neutral": {
  "light": { "hue": 210, "chroma": 0.02 },
  "dark":  { "hue": 220, "chroma": 0.04 }
}
```

For roles where the hue and chroma should remain stable across modes, use the single-object shorthand. Substrate will still derive the correct lightness for each mode independently.

## Reserved semantic roles

Substrate reserves the following role names. Each maps to a specific set of generated tokens and component usage patterns:

| Role | Purpose |
|---|---|
| `primary` | Brand identity, primary actions, key interactive elements such as buttons and links |
| `neutral` | Surfaces, borders, and body text; the backbone of your layout chrome |
| `error` | Destructive actions, validation failures, and critical alerts |
| `warning` | Cautionary states, non-blocking alerts, and degraded-service indicators |
| `success` | Confirmation states, completed actions, and positive feedback |
| `info` | Neutral informational messages and assistive hints |

<Note>
  You can extend the config with custom roles beyond the reserved set (e.g. `"brand-secondary"`), but reserved role names unlock additional generated token variants and built-in component bindings.
</Note>

## Generated CSS output

For each color intent, Substrate generates a family of tokens covering the role's fill, subtle background, and on-color (foreground) variants. APCA contrast values appear as inline comments so you can audit contrast at a glance without running a separate tool:

```css
/* Generated by Substrate — do not edit */
:root {
  --color-primary: oklch(62% 0.18 160);
  --color-primary-subtle: oklch(95% 0.04 160);
  --color-on-primary: oklch(99% 0.01 160); /* APCA Lc 87 */
}

[data-theme="dark"] {
  --color-primary: oklch(70% 0.18 160);
  --color-on-primary: oklch(5% 0.01 160); /* APCA Lc 82 */
}
```

<Note>
  APCA contrast values (e.g. `Lc 87`) appear as comments in every generated CSS file. Use them to verify compliance at a glance or to pipe into automated accessibility audits. An `Lc` value of `60` or above is generally considered sufficient for body text; `75+` for smaller text.
</Note>

<Tip>
  You do not need to define separate dark-mode hue or chroma values for most roles — Substrate derives dark-mode lightness automatically from the same intent. Only add a `light`/`dark` split when you want the *character* of the color (its hue or colorfulness) to shift between modes, not just its lightness.
</Tip>
