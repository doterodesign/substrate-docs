The brand config is where your design system begins. Instead of maintaining sprawling token spreadsheets or hand-authored style files, you declare your brand's intent in a single file — `substrate.config.json` — and Substrate computes every token value from it. Place this file at the root of your project or brand directory, and the system picks it up automatically at build time.

## The config file

`substrate.config.json` is a JSON (or YAML) file that describes everything Substrate needs to generate your full token set: color intent, spacing rhythm, type scale, motion vocabulary, and layout density. Here is a complete example showing all top-level fields:

```json
{
  "brand": "acme",
  "color": {
    "primary": { "hue": 160, "chroma": 0.18 },
    "neutral": { "hue": 210, "chroma": 0.02 }
  },
  "space-unit": "4px",
  "type-size-unit": "16px",
  "scale-ratio": 1.25,
  "motion-unit": "100ms",
  "density": "default",
  "cvd": ["deuteranopia", "protanopia"],
  "font": {
    "sans": "Inter, system-ui, sans-serif",
    "mono": "JetBrains Mono, Menlo, monospace"
  },
  "modes": ["light", "dark"],
  "contrast-targets": {
    "body-text": 75,
    "ui-components": 60
  }
}
```

## Top-level fields

<AccordionGroup>
  <Accordion title="brand">
    A short string identifier for this brand or product. Substrate uses it to namespace generated output files and — when you run multiple brands from a monorepo — to keep token sets distinct. Use a lowercase slug with no spaces (e.g. `"acme"`, `"brand-portal"`).
  </Accordion>

  <Accordion title="color">
    Describes color intent as hue and chroma pairs in OKLCH color space. You never specify hex values or lightness — Substrate's APCA contrast solver derives every lightness value based on the surface context in which the color appears. See [Color](/brand-config/color) for the full shape and all reserved semantic roles.
  </Accordion>

  <Accordion title="space-unit">
    The base unit of your spacing scale, expressed as a pixel value (e.g. `"4px"`). All spacing tokens are integer multiples of this unit. A 4px base gives you an 8px grid when using `--space-2`. Defaults to `"4px"`.
  </Accordion>

  <Accordion title="type-size-unit">
    The base (mid-point) font size of your type scale, expressed as a pixel value (e.g. `"16px"`). Scale steps above and below this value are computed using `scale-ratio`. Defaults to `"16px"`.
  </Accordion>

  <Accordion title="scale-ratio">
    The multiplier used to step up and down from `type-size-unit`. Common values include `1.25` (Major Third), `1.333` (Perfect Fourth), and `1.5` (Perfect Fifth). Defaults to `1.25`.
  </Accordion>

  <Accordion title="motion-unit">
    The base animation duration (e.g. `"100ms"`). All duration tokens — fast, normal, slow, slower — are multiples of this unit. Substrate also emits `prefers-reduced-motion` overrides automatically. Defaults to `"100ms"`.
  </Accordion>

  <Accordion title="density">
    Controls the spatial density of the spacing scale and component padding. Accepts `"compact"`, `"default"`, or `"comfortable"`. Switching density regenerates every spacing token without touching component code. Defaults to `"default"`.
  </Accordion>

  <Accordion title="cvd">
    An optional array of color-vision deficiency simulations to run during the build. Accepted values include `"deuteranopia"`, `"protanopia"`, and `"tritanopia"`. When specified, Substrate validates that generated color tokens meet APCA contrast targets under each named simulation and fails the build if any token falls short.
  </Accordion>

  <Accordion title="font">
    An optional map of font-family stacks. Define `sans` and/or `mono` to have Substrate generate `--font-sans` and `--font-mono` CSS custom properties and wire them into component recipes automatically. If omitted, Substrate falls back to system font stacks.
  </Accordion>

  <Accordion title="modes">
    An optional array of color-scheme modes to generate output for. Defaults to `["light", "dark"]`. Substrate generates a separate token set for each listed mode and outputs them as `[data-theme]` attribute selectors in CSS.
  </Accordion>

  <Accordion title="contrast-targets">
    An optional object that overrides the default APCA contrast thresholds Substrate uses when solving lightness values. Keys are semantic use-case names (e.g. `"body-text"`, `"ui-components"`) and values are target `Lc` scores. Use this when your product has stricter accessibility requirements than the built-in defaults.
  </Accordion>
</AccordionGroup>

## Defaults and overrides

Only `brand` and `color` are required. Every other field has a built-in default, so your config can be as minimal as you need. Override only what differs from the defaults:

```json
{
  "brand": "acme",
  "color": {
    "primary": { "hue": 160, "chroma": 0.18 },
    "neutral": { "hue": 210, "chroma": 0.02 }
  }
}
```

Substrate fills in `space-unit: "4px"`, `type-size-unit: "16px"`, `scale-ratio: 1.25`, `motion-unit: "100ms"`, and `density: "default"` for you. Add fields to the config only when you want to deviate from those defaults.
