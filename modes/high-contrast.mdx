High-contrast mode in Substrate is not an inversion filter and it does not fall back to black text on a white background. It is a full token recalculation: every foreground/background pair is re-solved with an APCA Lc 90+ target, using the same brand hues and chromas from your config. The result is a high-contrast theme that is still recognizably *your* product — just dramatically more legible.

## Two high-contrast modes

Substrate generates two distinct high-contrast variants so you cover users across both light and dark preferences.

<CardGroup cols={2}>
  <Card title="high-contrast" icon="sun">
    Built on a light base. Surfaces remain near-white and foreground tokens are darkened until they clear Lc 90 on their background. Activates automatically via `@media (prefers-contrast: more)` when the user's OS preference is light.
  </Card>
  <Card title="high-contrast-dark" icon="moon">
    Built on a dark base. Surfaces remain near-black and foreground tokens are lightened to Lc 90+. Serves users who need both a dark interface and maximum legibility — a combination most systems leave unaddressed.
  </Card>
</CardGroup>

## How the recalculation works

For each token in the standard light or dark set, Substrate re-runs APCA solving with the contrast target raised from the default (Lc 70 for body text) to Lc 90+. Hue and chroma are held constant; only lightness changes. This preserves the perceptual color identity of every role while maximising legibility.

The following example shows the same brand primary color — hue 160, chroma 0.22 — at its default light-mode lightness versus its high-contrast lightness.

```css
/* Default light */
[data-theme="light"] {
  --color-primary: oklch(62% 0.18 160); /* APCA Lc 70 on surface */
}

/* High contrast */
[data-theme="high-contrast"] {
  --color-primary: oklch(30% 0.22 160); /* APCA Lc 92 on surface */
}
```

The hue stays at 160 — the green-leaning brand color your users recognise — but the lightness drops from 62% to 30% so that the contrast against a near-white surface exceeds Lc 90. No manual override required.

<Note>
  Chroma may increase slightly in high-contrast mode, as shown above (0.18 → 0.22). Substrate allows a small chroma lift when it helps the solving algorithm reach the target lightness without pushing outside the sRGB gamut. You can disable this behaviour in your config by setting `"highContrast.chromaLift": false`.
</Note>

## Automatic OS preference detection

Substrate includes `@media (prefers-contrast: more)` in its CSS output. When the user has enabled "Increase Contrast" (macOS/iOS) or "High contrast" (Windows) in their system settings, the high-contrast theme activates automatically — no JavaScript, no client-side detection needed.

```css
@media (prefers-contrast: more) {
  :root:not([data-theme]) {
    --color-primary: oklch(30% 0.22 160);
    /* ... all high-contrast token values ... */
  }
}

@media (prefers-contrast: more) and (prefers-color-scheme: dark) {
  :root:not([data-theme]) {
    --color-primary: oklch(88% 0.20 160);
    /* ... all high-contrast-dark token values ... */
  }
}
```

The combined media query for `high-contrast-dark` checks both contrast and color-scheme preferences, so a user who prefers dark mode *and* increased contrast gets the correct variant automatically.

<Note>
  You can activate high-contrast mode manually by setting `data-theme="high-contrast"` on any container element — not just `<html>`. This is useful for individual UI sections that need extra legibility regardless of the user's system preference: an error banner, a data table in a dense dashboard, or an accessibility-focused component library that ships its own contrast guarantee.
</Note>

## Combining high-contrast with other modes

Because `data-theme` can be scoped to any element, you can mix modes within a single page. A common pattern is to render the main application in `dark` mode while ensuring that critical alert regions always use `high-contrast-dark`.

```html
<html data-theme="dark">
  <main>
    <!-- inherits dark tokens -->
  </main>

  <aside data-theme="high-contrast-dark">
    <!-- always maximum contrast, regardless of outer theme -->
  </aside>
</html>
```

<Tip>
  Use the scoped `data-theme` approach to progressively enhance legibility in the parts of your UI where errors, warnings, or critical status information appears. Your users who rely on high-contrast mode at the OS level are already served automatically — this technique lets you extend the same benefit to users who have not set a system-level preference.
</Tip>

## Verifying contrast in high-contrast output

Run `substrate audit` after building to get a full report of APCA Lc values across all modes, including both high-contrast variants. Any token pair that does not meet the target for its mode is flagged as a violation.

```bash
substrate audit --mode high-contrast
```

The audit output includes the token name, its computed APCA Lc value, the target, and the background token it was evaluated against — giving you everything you need to trace a violation back to the brand config value that caused it.
